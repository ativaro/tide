# A local correction attempt after a compiler diagnosis

The starting point are the 24 TIDE repairs of the [Priority Study](../17_prioritaeten/messung.json). The first submission of the third journal run with library failed due to a missing closing bracket. The new TIDE function receives exclusively the failed candidate, its submitted changes, and the actual compiler diagnosis. It can suggest a modified list of function bodies. Each correction must pass the same compiler and the same external acceptance test. The caller attempts this step at most once per model answer.

1. Trace 24 successful TIDE answers regularly on fresh copies. They must pass the acceptance test without correction.
2. For each answer for each fully bracketed function body individually, remove the last `)`. Use the actual compiler diagnoses. Upon successful correction, compare the entire submitted change with the original valid answer and execute the 40 public and 40 held-out cases of the respective project. Identical changes and the natural error may recur in this stress test. The test measures the coverage of this error pattern.
3. Verify counter-tests on the journal run. Removing an actual operand, two missing brackets, an additional closing delimiter, and a typo in the return value must fail after at most one attempt at the compiler. A syntactically correctable change with an additional domain error must fail at the public acceptance test. File selection, outdated body, CRLF, Unicode, text literals, and an inappropriate diagnosis location receive additional local TIDE examples.
4. Apply the actually failed **first** model answer to the unchanged source state. Measure twelve times in series the time from the availability of the answer to the passed public test run. This includes the first failed test run, the local correction attempt, and the re-acceptance. Held-out tests lie outside the time measurement. The historical tokens and the time to the first answer are in the individual log. Together with the new follow-up measurement, this yields a reconstructed total time. The original value for two model answers must be indicated separately.

No new model responses are generated for this replay. The programs, both test suites, and the Python comparison stem from the previously defined [experimental plan](../17_prioritaeten/versuchsplan.json). The replay can show whether an already observed second response was avoidable. The frequency of the error in other models or tasks remains open.
