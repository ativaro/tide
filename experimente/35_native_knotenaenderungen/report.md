# Change a TIDE expression in a project file

The native editor performs targeted changes to an entry file or one of its imported modules. An agent provides the project revision, a node identifier from `context` or `hole`, and the new operator or expression. The TIDE checker also knows the local names of a fold, a binding, or a rule at this point. It checks all examples of the project before adoption. [Editor](../../native/bootstrap/node_edits.tide) · [Transaction](../../native/bootstrap/editor_transaction.tide)

## Rebuild without Python on November 17, 2026

In an isolated Linux-x86-64 filesystem, only the production sources, build rules, starter, and system tools for the build were present. The build directory was empty. The Python interpreter, standard library, shared Python runtime, and experiment archive were unavailable to the build and the installed TIDE. There, `make check-native` and `make install` existed, including the byte-wise self-build comparison and the TIDE checks for the compiler, editor, Nano, and Space Invaders. All twelve stored ELF checksums for the six example programs matched. The six installed tools were byte-identical to those of a second local build. Both the checkout and the installed starter yielded a balance of `97` upon upgrade. Upon upgrading, eleven emulated old Python modules, eleven bytecode files, and the two previous starters disappeared. An additionally created foreign file remained intact. [Build rules](../../Makefile) · [Checksums and raw data](pruefung.json)

`make test` now contains a temporary balance file generated by the build that the editor actually changes via a node and that the checker retests afterward. Further permanent tests check the source limits of grouped and multi-line expressions, including a parameterless call in an imported module, Unicode, CRLF, and multiple changes with offset source lengths. For `play`, general file read permissions, and other value types, public native operations are still missing. Upon interactive start, the installation reported `E_BACKEND`. ## What becomes smaller during a repair

Four project copies each contained an intentionally incorrect expression. Before measurement, their examples failed; after takeover, they passed. For the two methods in the same project, candidate bytes and all response fields were identical. The tokens in the table count the content an agent must provide to make the change. Command options, context query, model reasoning, and possible retries are not included. Each time is the median of 15 calls to the installed tool with `--write` after three warm-up rounds. The methods swapped order on the same CPU core. [Individual times for preview and write](pruefung.json)

| Repair | Full File | Node Edit | Time with File | Time with Node |
|---|---:|---:|---:|---:|
| Balance, subtraction to addition | 120 Tokens | 12 Tokens | 7.67 ms | 7.69 ms |
| Ranking, reuse `on_equal` on tie | 312 Tokens | 14 Tokens | 8.23 ms | 8.40 ms |
| Report with import, cap negative values at zero | 240 Tokens | 13 Tokens | 8.42 ms | 8.47 ms |
| Fix addition in module from report | – | 17 Tokens | – | 8.37 ms |

In the last case, `adjustment.tide:2:1` denotes the target. `--source` replaces the entry file at the same project entry point, so there is no equivalent time comparison for this case. The three direct comparisons show significantly fewer transferred tokens and a small additional time cost for the node edit. Both previews still include the full candidate file. A new blind model repair or a speed comparison with Python was not part of this measurement.

## Acceptance of changes and error cases

- 236 different nodes in nine projects each received an order for an expression and for an operator. Further cases included erroneous JSON inputs, precision, type errors, revision conflicts, disallowed overlaps, accesses to local names, and the write state of both files during a module change. An order with 256 different changes in reverse source order was created.
- Out of 567 total cases, 562 matched the historical editor. For five replacements of entire `fold` expressions, this one fails with an internal error. In these five cases, the full expected source bytes were determined separately from the original token area and compared with the native preview. All five passed. The reference editor ran exclusively outside the isolated TIDE installation.
- In twelve groups with eight concurrent writers each on the same imported module, exactly one change was accepted. The other 84 reported `E_REVISION`. Entry file, file permissions, and the read project revision were checked in each group.
- The 176 comparisons for complete source files and the 1,950 previous comparisons for functions, rules, lists, inspections, and diagnoses passed again. [Sample sizes, individual measurements, and revisions](pruefung.json)
