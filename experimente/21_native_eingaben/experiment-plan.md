# Native runtime arguments

A Linux file for x86-64 is generated once from `degree_hours` to `apps/heating.tide`. The native call interface receives the start value and then zero to 4,096 list values as separate decimal arguments. The TIDE source and the domain computation are identical for each measurement series.

- The 29 programs from experiment 20 can also be called natively via their parameterized function. Compare the value or error code with the original target value and the TIDE reference. The previous closed heating degree hour file and the balance must continue to have the archived binary hashes.
- Check for empty lists, varying measurement series, i64 limits, leading zeros, missing or malformed arguments, list lengths 4,096 and 4.097, and a binding error after a computationally overflowing input on the reused heating degree hour program. For small text cases, the TIDE function provides the binding reference via `int`. Additionally, compare at least 100 deterministically generated inputs against the reference.
- Check for a direct and a forwarding program entry point to the reference standard of the work budget. Short and long branches, exactly 100,000 evaluated nodes, the first node above, and earlier arithmetic overflow are recorded separately. Count output, exit status, and error code.
- Measure local process time from start to output including input binding with CPython. Use identical positional arguments for both languages, maximum list length, and identical i66 error rules. Three sizes with 0, 16, and 4,096 measurements. For each size, six warm-up and 30 measurement pairs on the same logical CPU, with alternating order. The measurement series are provided before the call and varied between rounds. The target value is checked outside the process time. Record build time separately. This experiment measures neither the warm compute core nor the model costs.
