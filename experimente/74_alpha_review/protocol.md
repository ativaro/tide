# Stage 5 replication protocol

Use the complete order importer at commit `33f0972a2e001f3158630446f2e579ab355e0da1` and the original open-task baseline at `96c0a936b215ca21d3a58222b42ac96872f4d8b8`. Start each from a separate clean Git clone on the study filesystem. Check the pinned revision, empty working tree and absence of a build directory. Use the original installation and experiment commands, core 24 where available, and identical rights for TIDE and CPython. Sequence build, timing and verification jobs to avoid competing with another study process. Retain individual observations and acceptance results. Keep the 15 final tasks sealed. No model inference or model-based selection is part of Stage 5.

1. Repeat the original Stage 4 profile, component isolation, four workloads in both execution modes, and restart acceptance. Use the original fixtures and arm order.
2. Repeat the 15 open tasks with the original 0.6.5 tool, the CPython process-partition control, and the frozen vocabulary for offline counting. Check protocol identity and acceptance by task and language. Report measured tool performance separately from actual agent efficiency.
3. Run a batch-size counter-experiment on the final native importer and precompiled CPython reference. Use 8, 32, 128, 256, 384, 512 and 1,000 events. Each group of four consists of an order, redelivery, partial cancellation and redelivery. Keep the same warm-up, process timing boundary, SQLite settings, disk and full database checks. Alternate two arms with balanced first positions in the twelve measured pairs. Report the median within-pair time ratio and the range of tested sizes where the faster arm changes.

As a supplementary candidate check, repeat the same 15 open tasks and writing control with the 0.6.6 tool from the order-import revision. This distinguishes reproduction of the historical baseline from evidence about the actual release candidate. The public-alpha criterion is the same for both runs.

The roadmap accepts a reproducible runtime advantage on a representative task or a reproducible advantage in actual model tokens. It also requires a clean installation on a second machine for a public alpha. A same-machine replication can establish repeatability and delimit the workload claim. Decide explicitly whether the available evidence clears the public-alpha gate. [Roadmap](../../tasks/plan.md)
