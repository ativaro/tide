# Time for building a checked repair view

The previous method from trial 18 and the new TIDE workflow are compared. The source states of the previous workshop are bound by the hashes in the measurement data. The new workflow additionally checks a private copy of all read source files against the original project revision. The complete grouping comes from both methods from `tide context`.

- Eight time-paired repetitions per project for the Journal from trial 18, the deployment assignment with comparison library from trial 17, and the application `apps/report.tide`. In even and odd repetitions, the previous or new workflow starts alternately. Both run serially with fresh output directories.
- The monotone clock runs from the start of the project check to the finished grouped view and list of additional signatures. The local precheck before handover, the model answer, and the acceptance test after repair lie outside this interval.
- In each pair, ordered function bodies, additional signatures, and grouped context are compared. For Journal and deployment assignment, the stored model prompt must be generated byte-for-byte from this. No new model sessions are started for an identical input.
- Separately check on Nano (`step`), Space Invaders (`draw`), a state rule as an entry point, and a file with unusual formatting. If the previous assembly fails at the resource budget, distribute the old individual replacements over multiple calls using the same compiler forms and compare their finished view. Complete project copies with the grouped bodies are checked against the existing TIDE examples.
- If an embedded source file is changed subsequently, the deviating revision must be noticeable before handover of the view. For a root expression on a following line or after very deep indentation, the compiler's exact position query must function.
